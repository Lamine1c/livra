## 🎯 RÈGLE INVIOLABLE — PAS DE "LIVREUR LIVRA"

**LIVRA n'a PAS de livreurs officiels.** Les "livreurs perso" sont les livreurs **DU VENDEUR**, pas de LIVRA. 

→ Jamais écrire "livreur LIVRA", "notre livreur", "nos livreurs" dans aucune copy.
→ Toujours dire "le livreur de {{boutique}}" ou "votre livreur" (côté vendeur).
→ Raison : si un livreur fait un mauvais coup, LIVRA ne doit pas être responsable. Protection marque.

## 🐺 PUNCH LINES (à utiliser tel quel)

### Sur l'OTP anti-fausse-commande
> **"Le vendeur LIVRA pourrait dormir. Sa commande se confirme toute seule."**

Contexte : quand le client envoie son code OTP par WhatsApp, le webhook entrant le matche, met la commande à `confirmed` automatiquement, et le Realtime push l'update sur l'écran vendeur. Zéro intervention manuelle.

→ Punch contre les concurrents (Yalidine direct, gestion manuelle WhatsApp) : eux le vendeur **doit** confirmer à la main, taper le code, suivre les retours. LIVRA = passif pour le vendeur, actif pour le système.

### Sur les confirmatrices (le coût caché du e-commerce DZ)
> **"LIVRA = le tueur des confirmatrices."**

Contexte : la plupart des vendeurs DZ à +50 commandes/jour emploient 1 à 3 personnes à temps plein **juste pour appeler les clients et confirmer les commandes** (souvent leur épouse, leur sœur, un cousin). C'est leur **2e plus gros coût après les Facebook Ads**. Verbatim du marché : *"3 employés juste pour confirmer + suivre. C'est mon plus gros coût après les ads."*

LIVRA tue ce coût :
- L'OTP fait le travail de confirmation à leur place
- En darija, 24/7, sans pause café, sans congé maladie
- À 1500 DA/mois vs ~30 000 DA/mois pour une confirmatrice
- + le filtre anti-scam que même une humaine ne ferait pas

→ À utiliser comme angle d'attaque dans les ads Facebook DZ ciblées vendeurs à volume.

### Sur la promesse globale

- "Tue les fausses commandes avant qu'elles te coûtent"
- "Cash le jour même"

## 💡 ARGUMENTS DE VENTE (à intégrer dans la LP / ads / pitch)

### Argument 1 — L'auto-confirmation
**Sans LIVRA :** le vendeur reçoit la commande Facebook/WA → tape les infos dans Excel/carnet → appelle le client pour confirmer → re-tape le statut → galère.

**Avec LIVRA :** la commande arrive → le client reçoit un message WA avec son code → il répond le code → LIVRA confirme tout seul → le vendeur voit "Confirmée" apparaître sur son écran. **Sans rien faire.**

→ Gain de temps direct + zéro fausse commande qui passe.

### Argument 2 — Le tunnel anti-scam (OUI/NON + raisons)
Si le client tape NON ou ignore → LIVRA capture pourquoi (pas dispo / changé d'avis / trouvé moins cher). Le vendeur sait avant d'avoir préparé/expédié. Économie directe sur les retours et frais de livraison perdus.

### Argument 3 — Le suivi multi-mode unifié
Que le vendeur livre avec son livreur perso OU avec Yalidine/DHD/Anderson, l'acheteur reçoit UN lien de suivi propre dans WA. Le vendeur voit tout dans LIVRA. Plus de jonglage entre l'espace Yalidine, l'espace DHD, et WA.

# 📣 STRATÉGIE SOCIAL MEDIA LIVRA — « LA MACHINE » (gravée 10 juil 2026)

## Architecture des comptes
- **2 pages par plateforme, toutes sous le portfolio Meta « Plateforme LIVRA »** : page VENDEUR (acquisition) + page ACHETEUR (pull).
- **Réserver les handles MAINTENANT sur toutes les plateformes** (FB, IG, TikTok, YouTube Shorts) — même si vides. - Page acheteur — l'idée psychologique (Lamine) : amener l'acheteur à DEMANDER aux boutiques « vous travaillez avec LIVRA ? » → la pression remonte, mécanique Intel Inside / cadenas HTTPS.

## Cadence (réaliste solo + quadrille)
- **Pré-lancement** : 1 post/jour page vendeur (chauffer le marché, remplir les 50 fondateurs au jour J).
- **Post-lancement** : 2-3/jour via le KIT (Gary-V style : occuper l'espace — mais le volume ne devient une arme que quand la machine produit toute seule).
- **Batch production** : 1 session dédiée = 1 semaine de contenu d'avance. Sprint contenu 2-3j complets APRÈS la fin app+site (décision Lamine).
- La moitié du jeu Gary-V = les RÉPONSES : commentaires/DM traités chaque jour (>volume).
